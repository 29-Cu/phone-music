# QQ 音乐音源(自用)

> **只供自用。** 这个音源用的是**你自己的** QQ 音乐账号和会员:它像官方网页版一样,带着你的登录去取你本来就有权限播放的歌,不破解、不绕过任何付费。
> 下载下来的音频只存在你自己服务器的私有缓存里,只给你自己的播放端放。**不要把缓存的音频公开、分享、上传或转发给任何人**,也不要把缓存目录放进网站目录或代码仓库。

## 它是怎么工作的

1. AI 说要放「晴天 周杰伦」→ 先看本机缓存里有没有,有就直接用。
2. 没有就去 QQ 音乐搜,按搜索结果从上往下找第一条你能放的(第一条那一版放不了就试下一条,最多 4 条)。
3. 取播放链接,音质依次试 320k mp3 → 128k mp3 → 96k m4a,用第一个拿得到的。
4. 下载到本机私有缓存,播放端从 `/api/qq/<歌号>.mp3` 取(支持拖进度;要过你服务端的鉴权)。

放歌单里的歌时,如果某一首那一版没有权限(比如它在某张数字专辑里),会自动按歌名 + 歌手 + 时长找同一首的别的版本。对版本的规则很保守:歌名至少去掉括号后一致,且歌手或时长至少再对上一样,对不上宁可不放,也不会放成别人的翻唱。

## 第一步:开一个带远程调试的浏览器并登录

登录要扫码,所以需要一个你能看见窗口的 Chrome / Chromium(本机桌面、VNC 或远程桌面都行)。用单独的用户目录启动它,并打开远程调试端口:

```sh
google-chrome --remote-debugging-port=9222 --user-data-dir="$HOME/.config/phone-music-chrome"
# 或者 chromium --remote-debugging-port=9222 --user-data-dir="$HOME/.config/phone-music-chrome"
```

然后在这个浏览器里打开 <https://y.qq.com/>,用 QQ 或微信扫码登录。登录完**让这个浏览器一直开着**,留一个 y.qq.com 的标签页。

> 安全提醒:远程调试端口等于这个浏览器的遥控器。Chrome 默认只监听本机(127.0.0.1),**不要**把 9222 端口转发或暴露到公网。这个浏览器最好只用来登录音乐网站。

## 第二步:把登录抄给服务端

在项目目录下运行:

```sh
node tools/qq-login.js                       # 默认连 http://127.0.0.1:9222,写到 data/qq/
node tools/qq-login.js --cdp http://127.0.0.1:9333 --out /some/dir   # 换端口 / 换目录
```

它会从浏览器里读出 `*.qq.com` 的 cookie,写成:

- `cookie.txt`:登录 cookie,权限 600。**它等于你的登录,别给任何人看。**
- `meta.json`:只记登录 key 的到期时间,不含 cookie 内容,服务端用它判断「过期了没有」。

屏幕上只会打印 cookie 的**名字**,不会打印值。没写 `--out` 但设了 `QQ_COOKIE_FILE` 时,会写到那个文件(`meta.json` 放在同一目录)。

如果浏览器里已经没有登录(找不到 `qm_keyst` / `qqmusic_key`),它**不会**覆盖原来的文件,只提示你去登录,并以退出码 2 结束。

服务端每次用到 cookie 都会重新读文件,所以重新登录、重新跑一次这个工具以后**不用重启服务**。

## 第三步:定时刷新(每 6 小时)

QQ 音乐的登录 key 有效期不长。浏览器开着 y.qq.com 时通常会自己续登录,定时任务负责把最新的 cookie 抄过来。用 `crontab -e` 加一行(路径换成你自己的):

```cron
0 */6 * * * cd /path/to/phone-music && /usr/bin/node tools/qq-login.js --cdp http://127.0.0.1:9222 >> data/qq/login.log 2>&1
```

退出码 2 表示浏览器里没登录了,可以拿它做提醒。

## 服务端读的环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `QQ_COOKIE_FILE` | `./data/qq/cookie.txt` | 登录 cookie;`meta.json` 放在同一目录 |
| `QQ_CACHE_DIR` | `./data/qq/cache` | 下载下来的音频和 `index.json` |
| `QQ_CACHE_MAX_MB` | `2048` | 缓存上限,超了按「最久没放」先删 |

相对路径按项目目录算。歌单内容的缓存(6 小时)也放在 `data/qq/` 下面。`cookie.txt` 不存在或是空的,QQ 音乐这个音源就当没开。

## 登录过期了会怎样

- 判断过期的依据:`meta.json` 里的到期时间已过,或者 QQ 的取链接接口整体报错。单独某一首没权限(返回码 104003,常见于数字专辑、单曲付费)**不算**过期,会去找别的版本。
- 过期后,工具会回给 AI 一句清楚的话,大意是「QQ 音乐登录过期了,请在那个浏览器里重新登录,再跑一次 `node tools/qq-login.js`」,AI 会转告你。
- **已经缓存过的歌照样能放**,只是新歌放不了、歌单读不了。
- 处理:在那个浏览器里打开 y.qq.com 重新登录 → 跑一次 `node tools/qq-login.js`(或等定时任务)。不用重启。

## 为什么第一首要等一下

服务器在海外时,一首歌**第一次**从 QQ 音乐的 CDN 拉,可能要 0.3–15 秒才开始有数据;同一首**第二次**放直接走本地缓存,不到 0.5 秒。

所以放歌单时:第一首当场下好;后面的歌先登记下来,播放端放到第 i 首时,服务端顺手把第 i+1 首下好,歌与歌之间基本不用等。直接跳到更后面的某一首时,会在取的那一刻现下。

## 缓存

- 目录权限 700,文件 600;默认上限 2GB,超了按最久没放的先删(每放一次算一次「最近」)。
- 播放链接在内存里留 10 分钟,歌单列表 10 分钟,歌单里的歌 6 小时。
- `data/` 已经在 `.gitignore` 里,**不要**把它提交到仓库、放进网站目录、或打包发给别人。

## 排错

- **连不上浏览器的调试端口**:浏览器要用 `--remote-debugging-port` 启动,端口和 `--cdp` 一致;同一个用户目录已经开着一个没带调试参数的浏览器时,新参数不生效,先把它关掉。
- **提示没有 uin**:登录可能没完成,刷新 y.qq.com 确认已登录再跑。
- **偶尔搜不到**:QQ 的新搜索接口有时会被限流成空结果,这时会自动换老的搜索接口再搜一次。
- **某首一直放不了**:可能这首在你的会员范围外(数字专辑、单曲付费),也没有别的能放的版本。
